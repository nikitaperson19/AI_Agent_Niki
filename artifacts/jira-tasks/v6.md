## Task 1: Реализация механизмов выбора файлов (проводник + Drag-and-Drop)

| Поле | Значение |
|------|----------|
| **Local ID** | T-001 |
| **Summary** | Реализовать выбор файлов через проводник и Drag-and-Drop |
| **Description** | Реализовать компонент формы загрузки файла, поддерживающий два способа добавления файлов:\n\n1. **Выбор через проводник:** кнопка (например, «Обзор...» или «Выбрать файл»), открывающая стандартное диалоговое окно ОС для выбора файлов. Необходимо уточнить, поддерживается ли множественный выбор (multiselect) — см. Open Questions.\n\n2. **Drag-and-Drop:** выделенная зона интерфейса, поддерживающая перетаскивание одного или нескольких файлов мышкой из папки компьютера.\n\nОба способа должны передавать выбранные файлы в единый механизм валидации (см. Task 3). После успешной валидации файлы должны отображаться в форме (точное поведение после загрузки требует уточнения — см. Open Questions). |
| **Source Requirements** | REQ-01, REQ-02 |
| **Acceptance Criteria** | 1. При нажатии на кнопку «Обзор...» / «Выбрать файл» открывается стандартное диалоговое окно ОС для выбора файлов.\n2. Возможность перетаскивания одного или нескольких файлов в зону Drag-and-Drop.\n3. Выбранные/перетащенные файлы передаются в валидацию.\n4. Зона Drag-and-Drop имеет визуальный индикатор (подсветку) при наведении файла (требует уточнения). |
| **Dependencies** | Task 3 (Валидация) — должна быть готова для интеграции |
| **Priority** | HIGH — базовая функциональность формы |
| **Open Questions / Blockers** | 1. Поддерживается ли множественный выбор файлов через проводник? [AMB-06]\n2. Визуальные индикаторы зоны Drag-and-Drop (подсветка, анимация)? [MI-09]\n3. Поведение после успешной загрузки? [MI-08] |

## Task 2: Реализация вставки файлов из буфера обмена (Paste)

| Поле | Значение |
|------|----------|
| **Local ID** | T-002 |
| **Summary** | Реализовать вставку файлов из буфера обмена (Ctrl+V / Cmd+V) |
| **Description** | Реализовать возможность вставки файла (например, скриншота) с помощью комбинации клавиш Ctrl+V / Cmd+V в форму загрузки файла. Вставленный файл должен передаваться в единый механизм валидации (см. Task 3). Необходимо уточнить поддерживаемые типы файлов для вставки (только изображения или любые файлы) — см. Open Questions. |
| **Source Requirements** | REQ-03 |
| **Acceptance Criteria** | 1. При нажатии Ctrl+V / Cmd+V в фокусной области формы файл из буфера обмена вставляется.\n2. Вставленный файл передаётся в валидацию.\n3. Поддерживаемые типы файлов для вставки уточняются (см. Open Questions). |
| **Dependencies** | Task 3 (Валидация) — должна быть готова для интеграции |
| **Priority** | MEDIUM |
| **Open Questions / Blockers** | 1. Какие типы файлов поддерживаются для Paste (только изображения или любые)? [AMB-05]\n2. В каких ОС и браузерах должна работать вставка? [R-04] |

## Task 3: Реализация валидации загружаемых файлов

| Поле | Значение |
|------|----------|
| **Local ID** | T-003 |
| **Summary** | Реализовать валидацию загружаемых файлов (формат, размер, количество) |
| **Description** | Реализовать механизм валидации файлов, применяемый ко всем способам добавления (проводник, Drag-and-Drop, Paste). Валидация должна проверять:\n\n1. **Разрешённые форматы:** проверка расширения файла по заданному списку. При несовпадении — блокировка или сообщение об ошибке. Требуется регистронезависимая проверка.\n\n2. **Максимальный размер одного файла:** проверка, что каждый файл не превышает установленный лимит. Точное значение лимита требует уточнения (10 МБ или 48 МБ или другое).\n\n3. **Максимальное количество файлов:** проверка, что общее количество выбранных/загруженных файлов не превышает лимит. Точное значение и правила подсчёта требуют уточнения.\n\nВсе ошибки валидации должны отображаться пользователю. Способ отображения ошибок требует уточнения. |
| **Source Requirements** | REQ-04, REQ-05, REQ-06 |
| **Acceptance Criteria** | 1. Файл с неподдерживаемым расширением блокируется с сообщением об ошибке (регистронезависимая проверка).\n2. Файл, превышающий максимальный размер, блокируется с сообщением об ошибке.\n3. При превышении максимального количества файлов — блокировка с сообщением об ошибке.\n4. Валидация применяется единообразно ко всем способам добавления файлов. |
| **Dependencies** | Нет зависимостей от других задач |
| **Priority** | HIGH — критично для безопасности и UX |
| **Open Questions / Blockers** | 1. Точный список разрешённых форматов? [AMB-01]\n2. Точный максимальный размер одного файла? [AMB-02]\n3. Точное максимальное количество файлов? [AMB-03]\n4. Ограничение количества — на одну операцию или на всё время? [AMB-04]\n5. Есть ли ограничение на суммарный размер всех файлов? [AMB-08]\n6. Как должны отображаться ошибки валидации? [MI-07]\n7. Нужна ли проверка файлов нулевого размера? [B-01]\n8. Должен ли файл на границе лимита проходить валидацию? [B-02] |
