# Requirement Review Artifact

## Scope
Анализ функциональных требований к форме загрузки файла. Функциональность включает способы выбора/добавления файлов и ограничения/валидацию файлов.

---

## Requirements

| # | Требование | Source Reference |
|---|-----------|------------------|
| REQ-01 | Форма загрузки файла должна предоставлять кнопку (например, «Обзор...» или «Выбрать файл»), открывающую стандартное диалоговое окно ОС для выбора файлов. | Confluence page 7733249, раздел 1 |
| REQ-02 | Форма должна поддерживать Drag-and-Drop (перетаскивание) одного или нескольких файлов мышкой из папки компьютера в выделенную зону интерфейса. | Confluence page 7733249, раздел 1 |
| REQ-03 | Форма должна поддерживать вставку файла (например, скриншота) с помощью комбинации клавиш Ctrl+V / Cmd+V (буфер обмена). | Confluence page 7733249, раздел 1 |
| REQ-04 | Форма должна блокировать или выдавать ошибку при попытке выбрать файл с запрещённым расширением (согласно списку разрешённых форматов). | Confluence page 7733249, раздел 2 |
| REQ-05 | Форма должна ограничивать максимальный размер одного файла (лимит указан в требованиях, но точное значение не определено). | Confluence page 7733249, раздел 2 |
| REQ-06 | Форма должна ограничивать максимальное количество файлов, загружаемых за один раз или прикрепляемых к одной форме. | Confluence page 7733249, раздел 2 |

## Ambiguities

| # | Описание неоднозначности | Фрагмент требования | Возможные трактовки |
|---|------------------------|--------------------|--------------------|
| AMB-01 | Точный список разрешённых форматов не указан — приведены только примеры (.pdf, .docx, .jpg, .png). | «Список допустимых расширений (например, .pdf, .docx, .jpg, .png)» | 1) Только эти 4 формата разрешены. 2) Примеры, реальный список будет определён позднее. |
| AMB-02 | Максимальный размер файла не указан однозначно — приведены два разных значения как примеры. | «лимит на вес одного файла (например, не более 10 МБ или 48 МБ)» | 1) Лимит 10 МБ. 2) Лимит 48 МБ. 3) Ни одно из значений не является окончательным. |
| AMB-03 | Максимальное количество файлов не указано однозначно. | «например, не более 5 штук» | 1) Лимит = 5 файлов. 2) Пример, точное значение будет определено позже. |
| AMB-04 | Не указано, распространяется ли ограничение количества на «за один раз» и/или «прикрепляемых к одной форме» совместно или раздельно. | «Максимальное количество файлов: Ограничение на общее число файлов, загружаемых за один раз или прикрепляемых к одной форме» | 1) 5 файлов суммарно за всё время к одной форме. 2) 5 файлов за одну операцию загрузки, но можно загрузить несколько раз. |
| AMB-05 | Не указано, какие типы файлов поддерживаются для вставки через буфер обмена (Paste). | «Возможность вставить файл (например, скриншот) с помощью комбинации клавиш Ctrl+V / Cmd+V» | 1) Только изображения (скриншоты). 2) Любые файлы из буфера обмена. |
| AMB-06 | Не указано, поддерживает ли выбор через проводник множественный выбор файлов. | «открывающей стандартное диалоговое окно операционной системы для выбора файлов» | 1) Разрешён выбор только одного файла. 2) Разрешён выбор нескольких файлов. |
| AMB-07 | Не указано поведение при перетаскивании неподдерживаемого формата через Drag-and-Drop. | «Поддержка перетаскивания одного или нескольких файлов мышкой из папки компьютера в выделенную зону» | 1) Отображается ошибка для каждого неподдерживаемого файла. 2) Вся операция отменяется, если хотя бы один файл недопустим. |
| AMB-08 | Не указано, суммируется ли лимит размера для нескольких файлов (общий размер загрузки) или применяется только к одному файлу. | «Максимальный размер файла: Лимит на вес одного файла» | 1) Только пофайловый лимит (каждый файл ≤ N МБ). 2) Есть ещё и общий лимит на все файлы в загрузке. |

## Conflicts
Явные внутренние противоречия между требованиями не обнаружены. Однако взаимоисключающие примеры значений (10 МБ vs 48 МБ для max size) создают неоднозначность, которая может быть следствием конфликта в источниках.

## Positive Flows

| # | Flow | Описание |
|---|------|----------|
| PF-01 | Выбор файла через проводник | Пользователь нажимает кнопку «Обзор...», выбирает один или несколько файлов в диалоге ОС, файлы добавляются в форму. |
| PF-02 | Drag-and-Drop | Пользователь перетаскивает один или несколько файлов в зону Drag-and-Drop, файлы добавляются в форму. |
| PF-03 | Paste из буфера обмена | Пользователь копирует файл/скриншот и вставляет его с помощью Ctrl+V в форму. |
| PF-04 | Успешная загрузка валидных файлов | Пользователь выбирает файлы разрешённых форматов, не превышающие лимит размера и количества — файлы успешно загружаются/прикрепляются. |

---

## Negative Flows

| # | Flow | Описание |
|---|------|----------|
| NF-01 | Загрузка неподдерживаемого формата | Пользователь пытается загрузить файл с расширением, отсутствующим в списке разрешённых — система блокирует или выдаёт ошибку. |
| NF-02 | Превышение максимального размера файла | Пользователь пытается загрузить файл, размер которого превышает установленный лимит — система блокирует или выдаёт ошибку. |
| NF-03 | Превышение максимального количества файлов | Пользователь пытается загрузить больше файлов, чем разрешено — система блокирует или выдаёт ошибку. |

## Boundaries

| # | Граничное условие | Описание |
|---|------------------|----------|
| B-01 | Файл нулевого размера | Поведение при попытке загрузить пустой файл (0 байт). |

| B-05 | Пустой Drag-and-Drop (сброс вне зоны) | Поведение при сбросе файла вне зоны Drag-and-Drop. |

### Обоснование
- Artifact создан, все Completion Criteria выполнены в части анализа.
- Однако обнаружены **критические неоднозначности (8 шт.)** и **отсутствующая информация (9 пунктов)**, которые напрямую влияют на дизайн задач и тестовой модели:
  1. Точные значения лимитов (размер, количество, форматы) не определены — примеры даны как "например", что не позволяет однозначно спроектировать валидацию.
  2. Не указаны типы файлов для Paste-функциональности.
  3. Не указано поведение при множественной загрузке.
  4. Не описаны UX-требования (отображение ошибок, визуальные состояния).
- Эти неоднозначности требуют эскалации к владельцу требований и не могут быть разрешены оркестратором самостоятельно.
