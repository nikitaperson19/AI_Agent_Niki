## Scope

Анализируемая функциональность — **форма авторизации пользователя** (Login Form), включающая:
- UI-компоненты формы (поля ввода, кнопки, ссылки, чекбокс, иконка видимости пароля);
- логику клиентской валидации (заполненность полей, формат логина);
- логику серверной аутентификации (успешный вход, неверные учётные данные, блокировка при переборе);
- поведение сессии (HttpOnly cookie, редирект после успешного входа).

Функциональность регистрации и восстановления пароля **не входит** в Scope — на форме присутствуют только ссылки на эти разделы.

| REQ-AUTH-001 | Форма авторизации содержит два обязательных текстовых поля: «Логин» (email или номер телефона) и «Пароль». | Confluence page, section 1 |

| REQ-AUTH-007 | При отправке пустой формы незаполненные поля подсвечиваются красным, под каждым выводится текст: «Поле обязательно для заполнения». | Confluence page, section 2 |
| REQ-AUTH-008 | Система проверяет формат логина (email regex или международный номер телефона). При ошибке формата — сообщение: «Некорректный формат логина или телефона». | Confluence page, section 2 |
| REQ-AUTH-009 | Логин приводится к lowercase перед проверкой в БД; пароль регистрочувствителен. | Confluence page, section 2 |
| REQ-AUTH-010 | Успешный вход: система создаёт сессию, устанавливает HttpOnly cookie, перенаправляет на главную/личный кабинет. | Confluence page, section 3 |
| REQ-AUTH-011 | Неверные учётные данные: система выводит общее сообщение «Неверный логин или пароль» (без указания, что именно неверно). | Confluence page, section 3 |

## Ambiguities

| ID | Фрагмент требования | Варианты трактовки |
|----|--------------------|--------------------|
| AMB-001 | REQ-AUTH-012: «Фиксация 5 подряд неудачных попыток авторизации с одного IP-адреса или для конкретного логина в течение 3 минут» | 1) Блокировка наступает при превышении лимита по **любому** из критериев (IP ИЛИ логин). 2) Блокировка наступает при превышении лимита **одновременно** по обоим критериям (IP И логин). 3) Счётчики ведутся раздельно для IP и для логина. Трактовка «или» допускает любую из интерпретаций. |
| AMB-002 | REQ-AUTH-010: «перенаправляет пользователя на главную страницу / в личный кабинет» | Не указано, какой именно URL является целевым (главная страница или личный кабинет) и от каких условий зависит выбор. |
| AMB-003 | REQ-AUTH-012: Сообщение «Попробуйте позже через ХХ минут» | Не указано, как рассчитывается «ХХ минут» — остаток до окончания блокировки, фиксированное значение 15, или динамическое значение. |
| AMB-004 | REQ-AUTH-006: Чекбокс «Запомнить меня» | Не описано поведение при установленном чекбоксе — продлевается ли сессия, устанавливается ли persistent cookie, какой срок действия. |

## Missing Information

| ID | Описание | Impact |
|----|----------|--------|
| MISS-001 | Не определён максимальный/минимальный допустимый размер полей (логин, пароль). | Невозможно определить граничные тесты для длины вводимых данных. |
| MISS-002 | Не указан формат международного номера телефона (с '+' или без, количество цифр). | Невозможно однозначно реализовать и протестировать валидацию телефона. |
| MISS-003 | Не описан target URL после успешного входа (главная страница или личный кабинет). | Невозможно однозначно проверить финальное состояние после успешного входа. |
| MISS-004 | Не описано точное поведение блокировки при переборе: сбрасывается ли счётчик после успешного входа; сбрасывается ли по истечении 3-минутного окна; что считается «подряд» — строго последовательные или любые 5 за 3 минуты. | Неоднозначность логики блокировки. |
| MISS-005 | Не указано поведение для чекбокса «Запомнить меня» (техническая реализация). | Невозможно протестировать функциональность «Запомнить меня». |
| MISS-006 | Не указано поведение кнопки «Войти» после отправки формы (должна ли она становиться disabled для предотвращения повторной отправки). | Риск повторной отправки формы. |
| MISS-007 | Не указано поведение для ссылок «Забыли пароль?» и «Зарегистрироваться» (открываются в том же окне или новом; ведут на существующие страницы). | Невозможно протестировать навигацию. |
| MISS-008 | Не указаны требования к сообщению об ошибке при блокировке — динамическое ли «ХХ минут» (сколько осталось) или статическое «15 минут». | Неоднозначность при проверке сообщения. |
