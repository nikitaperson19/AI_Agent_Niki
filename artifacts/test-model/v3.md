**Соглашения по тестовым данным:**
- Существующий пользователь: логин `qa.user@example.com` (в БД хранится в нижнем регистре), пароль `ValidPass123`.
- Существующий пользователь с телефоном: логин `+79001234567`, пароль `ValidPass123`.
- Отсутствующий в БД логин: `no.such.user@example.com`.
- Для сюиты S5 требуется управляемый сброс счётчиков неудачных попыток и состояния блокировки между тестами, а также возможность управлять серверным временем/паузами.
- Значения логина, не являющегося ни email, ни международным номером телефона: `qa.user` (без `@`), `12-34`.

**Ограничения модели (не додумывались):**
- Конкретные regex email/телефона и перечень допустимых телефонных форматов требованиями не заданы → проверяются только заведомо валидные и заведомо невалидные значения, без проверки границы регулярного выражения.
- Точный формат подстановки «ХХ минут» не задан → проверяется дословный текст сообщения, а не конкретное число минут.
- Атрибуты cookie кроме `HttpOnly` и срок жизни cookie не заданы → проверяется только наличие флага `HttpOnly`.
- Точка редиректа задана как «главная страница / личный кабинет» → в ожидаемом результате допускаются оба варианта, конкретный URL не фиксируется.
- Целевые адреса «Забыли пароль?» / «Зарегистрироваться» не заданы → проверяется кликабельность и реакция на клик, а не целевая страница.

### 6.2 Внутренние пересечения v3

Разведены, дублей нет:
- TC-UI-02 (плейсхолдеры) ↔ TC-PV-01 (маска) — разные части REQ-AUTH-002.
- TC-UI-03 (disabled при неполной заполненности) ↔ TC-UI-04 (переход в активное состояние и обратно) — разные состояния модели кнопки.
- TC-VAL-01 (оба поля пусты) ↔ TC-VAL-02/03 (одно поле пусто) — разные классы таблицы решений.
- TC-VAL-02 ↔ TC-VAL-03 — зеркальные кейсы, различаются проверяемым полем (адресность ошибки).
- TC-VAL-04 (email-ветка) ↔ TC-VAL-05 (телефонная ветка) — разные ветки REQ-AUTH-008.
- TC-AUTH-03 (неверная пара) ↔ TC-AUTH-05 (регистр пароля) — разные причины отказа; в TC-AUTH-05 проверяется именно регистрочувствительность.
- TC-PV-02 (включение видимости) ↔ TC-PV-03 (возврат маски) ↔ TC-PV-04 (сохранение значения при переключениях) — разные проверяемые аспекты REQ-AUTH-003.

- TC-BF-02 (блокировка по логину) ↔ TC-BF-05 (блокировка по IP) — два независимых признака из REQ-AUTH-012.
- TC-BF-02 ↔ TC-BF-03 — механизм блокировки ↔ попытка обхода блокировки знанием пароля.
